============================================================

1.1. Пользователи:

1.2. Язык и валюта:
- Интерфейс только на русском.
- Валюта только RUB.
- Если пользователь указывает другую валюту, вежливо ответить: "Пока я поддерживаю только рубли".

1.3. Ввод данных:
- Только ручной ввод: текст и голосовые сообщения.

- Текущий баланс = стартовый баланс + доходы - расходы.
- Переводы не влияют на текущий баланс.
- Пополнения целей не считаются расходами в общем балансе, но учитываются в целях.

3. ПАРСЕР ТЕКСТА
============================================================

Создай модуль services/parser.py.

Парсер должен работать в двух режимах:
1. rule_based — обязательно, работает без LLM.
2. llm — опционально, если включён LLM_PROVIDER=ollama или другой локальный OpenAI-compatible endpoint.

Если LLM недоступен или вернул некорректный JSON, всегда fallback на rule_based.

3.1. Требования к rule_based:
- Определять expense по словам: купил, купила, потратил, потратила, оплатил, оплатила, заплатил, заплатила, трата, расход.
- Определять income по словам: получил, получила, зарплата, аванс, пришли, поступило, заработал, заработала, доход, кэшбэк.
- Определять transfer по словам: перевёл, перевела, перевод, перекинул, перекинула, с карты на счёт, со счёта на карту.
- Определять goal_contribution по словам: отложил, отложила, в копилку, на цель, пополнил цель, добавил к цели.

3.2. Извлечение суммы:
Поддерживать форматы:
- 200
- 200.50
- 200,50
- 200 р
- 200 руб
- 200 рублей
- 200₽
- 5к = 5000
- 1.5к = 1500
- 2 тыс = 2000
- 80к = 80000

Если сумма не найдена, не сохранять ничего и попросить уточнить:
"Не смог найти сумму. Напиши, например: купил кофе за 250 рублей."

3.3. Извлечение даты:
- Если дата не указана — сегодня.
- Поддерживать: сегодня, вчера, позавчера, DD.MM.YYYY, DD.MM.
- Если год не указан, использовать текущий год; если дата получилась в будущем дальше +1 дня, спросить подтверждение даты или использовать сегодня.

3.4. Извлечение категории:
Использовать словарь ключевых слов:
- кофе, кафе, ресторан, пицца, суши, доставка еды -> Кафе и рестораны
- продукты, магазин, пятёрочка, магнит, лента, вкусвилл, ашан -> Продукты
- такси, метро, автобус, бензин, заправка, каршеринг -> Транспорт
- аптека, лекарства, врач, анализы -> Здоровье
- жкх, коммуналка, квартплата -> ЖКХ
- интернет, связь, мобильный, оператор -> Связь и интернет
- подписка, spotify, яндекс плюс, kinopoisk, netflix -> Подписки
- одежда, куртка, обувь -> Одежда
- кино, концерт, игра, развлечение -> Развлечения
- подарок, день рождения -> Подарки
- обучение, курс, книга -> Образование
- зарплата, аванс -> Зарплата/Аванс

Если категория не определена, использовать "Прочее" и confidence низкий.
Если confidence категории ниже 0.7, после подтверждения предложить выбрать категорию вручную.

3.5. Несколько операций:
Если сообщение содержит несколько сумм и разделители: ",", "и", "потом", "а", "ещё", пытаться разделить на несколько операций только если каждая часть имеет сумму и понятный контекст.

5. ЦЕЛИ И НАКОПЛЕНИЯ
============================================================

Создай модуль services/goals.py.

5.1. Поля цели:
- id
- title
- target_amount: Decimal
- current_amount: Decimal
- currency: RUB
- deadline: Optional[date]
- apy: Optional[float], годовая ставка в процентах
- monthly_contribution_plan: Optional[Decimal]
- status: active | paused | done
- created_at

5.2. Создание цели:
Команда /goal_new запускает пошаговый мастер:
1. Название цели.
2. Целевая сумма.
3. Сколько уже накоплено.
4. Срок: количество месяцев или дата.
5. Годовая ставка, если есть. Если нет — 0.
6. Желаемый ежемесячный взнос, если есть.

После ввода данных показать расчёт:
- сколько нужно накопить;
- сколько уже есть;
- срок;
- требуемый ежемесячный взнос;
- прогноз с учётом ставки;
- достижимость при текущем свободном остатке, если он известен.

5.3. Детерминированные расчёты:
LLM не должен сам считать проценты. Все расчёты только в коде.

Использовать месячную ставку:
monthly_rate = (1 + apy / 100) ** (1/12) - 1

Если apy = 0, monthly_rate = 0.

Функции:
- projected_value(current_amount, monthly_amount, months, apy)
- required_monthly(current_amount, target_amount, months, apy)
- months_to_goal(current_amount, target_amount, monthly_amount, apy)

Формула будущей стоимости при взносе в конце месяца:
FV = current_amount * (1 + r)^n + monthly_amount * (((1 + r)^n - 1) / r)

Если r = 0:
FV = current_amount + monthly_amount * n

Если нужно найти monthly_amount:
PMT = (target_amount - current_amount * (1 + r)^n) * r / ((1 + r)^n - 1)

Если r = 0:
PMT = (target_amount - current_amount) / n

Обработать краевые случаи:
- target_amount <= current_amount: цель уже достигнута.
- monthly_amount <= 0 и target_amount > current_amount: вернуть None или бесконечность.
- months <= 0: вернуть ошибку.
- apy < 0: считать 0.

5.4. Пополнение цели:
Если пользователь пишет "отложил 5000 на отпуск":
- parser определяет goal_contribution.
- Если активная цель одна, пополнить её после подтверждения.
- Если целей несколько, показать выбор цели.
- Если цель не найдена, спросить: "Сначала создай цель командой /goal_new".

Пополнение цели создаёт запись goal_contribution и увеличивает current_amount цели.

5.5. Отображение цели:
"Цель: Отпуск
Нужно: 300 000 ₽
Уже накоплено: 132 000 ₽
Прогресс: 44%
Срок: 8 месяцев
Требуемый взнос: 22 700 ₽/мес
Статус: идёт по плану / отстаёт от плана"

6. СОВЕТЫ ПО КНОПКЕ
============================================================

Создай модуль services/advice.py.

Советы даются только по команде /advice или кнопке "💡 Дай совет".

6.1. Детерминированный advice engine обязателен.
Он должен работать даже без LLM.

Анализировать:
- доходы за последние 30 дней;
- расходы за последние 30 дней;
- доходы и расходы за предыдущие 30 дней;
- топ-3 категории расходов;
- категорию "Подписки";
- норму сбережения: net / income;
- активные цели и требуемый ежемесячный взнос;
- средний свободный остаток за месяц.

6.2. Правила советов:
Если данных мало:
"Пока мало данных. Добавь несколько доходов и расходов, и я смогу дать полезный совет."

Если норма сбережения < 10%:
Предложить настроить автоперевод 5% от дохода.

Если категория выросла больше чем на 20% по сравнению с предыдущим периодом и сумма категории > 1000 ₽:
Предложить сократить категорию на 10-15% и показать примерный эффект.

Если сумма подписок > 500 ₽/мес:
Предложить проверить подписки.

Если активная цель требует ежемесячный взнос выше среднего свободного остатка:
Сообщить, что цель может быть не достигнута, и предложить варианты:
- продлить срок;
- увеличить взнос;
- уменьшить цель;
- найти дополнительный доход;
- сократить одну из категорий.

Если нет цели "Подушка безопасности" и расходы за месяц > 0:
Предложить создать небольшой резерв.

6.3. Формат советов:
Выводить 3-5 пунктов.
Каждый пункт:
💡 Заголовок
Что сделать: ...
Ожидаемый эффект: ...
Почему это важно: ...

6.4. Тон:
- дружелюбный;
- без осуждения;
- без фраз "ты слишком много тратишь";
- без обещаний дохода;
- без инвестиционных рекомендаций по конкретным активам.

6.5. Опциональный LLM-режим:
Если LLM_PROVIDER=ollama и модель доступна, можно передавать детерминированные факты в LLM и просить красиво переформулировать советы.
Запрещено разрешать LLM менять числа, выдумывать новые факты или давать финансовые рекомендации по активам.

Создай файл prompts/advice_system.txt со смыслом:
"Ты — дружелюбный финансовый помощник. Используй только предоставленные факты. Не меняй числа. Не выдумывай данные. Не давай индивидуальных инвестиционных рекомендаций. Верни 3-5 коротких советов на русском."

8. TELEGRAM MINI WEB APP
============================================================

Создай простой Mini Web App без тяжёлого SPA-фреймворка.
Использовать FastAPI + Jinja2 + vanilla JS + обычный CSS.
Не использовать внешние CDN, кроме официального Telegram WebApp SDK, если это необходимо.

Маршруты:
- GET /app — главная страница Mini App.
- GET /api/summary — сводка за текущий месяц.
- GET /api/transactions — последние операции.
- GET /api/goals — список целей.
- GET /healthz — healthcheck.

Авторизация Mini App:
- Проверять Telegram WebApp initData.
- Проверять HMAC-подпись согласно документации Telegram.
- Разрешать доступ только пользователям из ALLOWED_TELEGRAM_IDS.
- Если initData невалидна, вернуть 401.

Главная страница Web App должна показывать:
- текущий баланс;
- доходы за месяц;

10. БЕЗОПАСНОСТЬ
============================================================

Обязательно реализовать:

10.1. Доступ:
- Все команды и сообщения обрабатывать только если telegram_id есть в ALLOWED_TELEGRAM_IDS.
- Для чужих пользователей отвечать: "Доступ запрещён."
- В логах не хранить содержимое сообщений при DEBUG=false.

10.2. Секреты:
- BOT_TOKEN, SECRET_KEY, ALLOWED_TELEGRAM_IDS только в .env.
- Никаких секретов в коде, git, логах, ответах пользователю.
- .env добавить в .gitignore.
- Создать .env.example.

10.3. Голос:
- Аудио хранить только во временной папке.
- Удалять сразу после STT.
- Не сохранять аудио в базе.

10.4. LLM:
- Если LLM используется, не отправлять в него пароли, seed, номера карт.
- В пользовательском тексте нет таких данных, но в промпте указать запрет на обработку чувствительных данных.
- Если LLM недоступен, бот продолжает работать в rule_based режиме.

10.5. Callback buttons:
- Callback data должна быть подписана HMAC с SECRET_KEY или содержать случайный draft_id, который проверяется по базе.
- Перед выполнением callback проверять telegram_id пользователя и срок действия draft.

10.6. Web App:
- Проверять Telegram initData.
- Не доверять user.id из initData без проверки подписи.
- Возвращать 401 при ошибке.
- Не отдавать приватные данные без initData.

10.7. Валидация:
- Все входящие суммы через Decimal.
- Сумма > 0.
- Сумма не больше 1000000000.
- Дата не позже +1 дня от текущего момента и не раньше 2000-01-01.
- Длина текстовых сообщений ограничена 4000 символов.
- Длина голосовых ограничена 120 секундами.

10.8. Удаление данных:
/delete_all показывает предупреждение и требует два подтверждения inline-кнопками:
"Точно удалить все данные?" -> "Да, удалить безвозвратно".
После удаления очистить transactions, goals, goal_contributions, operation_drafts, advice_logs, settings, но оставить users, чтобы бот мог снова работать.

10.9. Экспорт:
/export создаёт CSV-файл:
- transactions.csv
- goals.csv
Отправляет документы пользователю.
Файлы не хранить дольше, чем нужно для отправки.

10.10. Логирование:
- Логировать только технические события: startup, webhook/polling, ошибки.
- Не логировать тексты операций, голос и суммы, если DEBUG=false.

14. DEPLOYMENT
============================================================

14.1. Локальная разработка:
- MODE=polling
- запуск: python -m app.main
- Mini App доступен локально через ngrok/cloudflared, если нужно протестировать Telegram WebApp.

14.2. Production:
- MODE=webhook
- BASE_URL=https://domain.example
- FastAPI за reverse proxy Caddy или nginx.
- Caddy автоматически получает HTTPS-сертификат.
- Webhook устанавливается с secret_token.
- Telegram Mini App URL указывает на BASE_URL/app.

Создать Caddyfile.example:
{$DOMAIN} {
    reverse_proxy app:8000
}

docker-compose должен включать:
- app
- caddy с профилем web
- ollama с профилем llm

Пример запуска production:
docker compose --profile web up -d
Пример с локальным LLM:
docker compose --profile web --profile llm up -d

17. КРИТЕРИИ ГОТОВНОСТИ MVP
============================================================

MVP считается готовым, если:

1. docker compose поднимает бота и web app.
2. /start работает только для двух ALLOWED_TELEGRAM_IDS.
3. Текст "купил шоколадку за 200 рублей" создаёт расход 200 ₽ с категорией и подтверждением.
4. Голосовое сообщение с той же фразой распознаётся локально и создаёт такой же черновик.
5. После подтверждения операция появляется в базе и в Mini App.
6. /report показывает доходы, расходы и свободный остаток.
7. /goal_new создаёт цель и считает требуемый ежемесячный взнос.
8. Фраза "отложил 5000 на отпуск" пополняет цель "Отпуск", если она одна.
9. /advice даёт 3-5 детерминированных советов без LLM.
10. Mini App показывает баланс, месячную сводку, цели и последние операции.
11. Голосовые файлы не сохраняются после обработки.
12. Нет крипты, bank-API, платежей и внешних финансовых операций.
13. Все суммы только в RUB.
14. Все операции сохраняются только после подтверждения пользователя.
