## 🔴 Критические проблемы безопасности (P0)

### 1. Захардкоженный API-ключ OCR

**Файл:** `app/bot/handlers/add.py:256`

```python
data = {
    'apikey': 'helloworld',  # ← ЗАХАРДКОЖЕН, публично известный ключ
```

**Риск:** Это публичный демо-ключ. В продакшене кто угодно может злоупотребить вашим квотом OCR.

**Решение:** Перенести в `settings.OCR_API_KEY` с конфигурацией через `.env`.

---

### 2. Обход аутентификации в Web App

**Файл:** `app/web/auth.py:97-99`

```python
if settings.ALLOWED_TELEGRAM_IDS:
    default_user_id = sorted(list(settings.ALLOWED_TELEGRAM_IDS))[0]
    return {"id": default_user_id, "first_name": "Пользователь"}
```

**Риск:** Если `initData` отсутствует/невалиден И нет параметра `uid`, система возвращается к первому разрешённому пользователю без какой-либо аутентификации. Это означает, что неаутентифицированные запросы могут получить доступ к любому эндпоинту от имени этого пользователя.

**Решение:** Убрать этот fallback или требовать валидную аутентификацию для чувствительных операций.

---

### 3. Отсутствие валидации входных данных в Web Routes

**Файл:** `app/web/routes.py:397-418`

```python
@router.post("/api/user-settings")
async def save_user_settings(data: dict, user: dict = Depends(get_current_web_user)):
```

**Риск:** Принимает произвольный `dict` без валидации схемы. Злонамеренный ввод может внедрить нежелательные ключи.

**Решение:** Создать правильную Pydantic-схему для пользовательских настроек.

## 🟠 Проблемы архитектуры (P1)

### 1. Монолитный файл обработчика

**Файл:** `app/bot/handlers/add.py` (660 строк)

- Содержит бизнес-логику, операции с БД, функции форматирования и обработчики
- Нарушает принцип единственной ответственности (SRP)
- Сложно тестировать и поддерживать

---

### 2. Дублирование управления сессиями

**Файлы:** Множество обработчиков

```python
async with AsyncSessionLocal() as session:
    # ... повторяется в каждом обработчике
```

**Решение:** Создать систему dependency injection или базовый класс обработчика.

---

### 3. Ленивые импорты внутри функций

**Файлы:** `app/bot/handlers/add.py:132-136`, `app/web/routes.py:276-278`

```python
async def handle_photo_message(message: Message, bot: Bot):
    import uuid
    from datetime import datetime, timedelta
    from app.services.accounts import record_user_activity
```

**Влияние:** Затрудняет чтение кода, скрывает зависимости.

---

### 4. Отсутствие сервисного слоя для некоторых операций

- Расчёты балансов выполняются инлайн в обработчиках
- Нет централизованного сервиса валидации

---

## 🟡 Проблемы качества кода (P1)

### 1. Смешанные ответственности в Routes

**Файл:** `app/web/routes.py:274-377`

- Эндпоинт профиля загружает аватар из Telegram API
- Бизнес-логика смешана с вызовами API
- 100+ строк в одной функции

---

### 2. Непоследовательная обработка ошибок

- Некоторые обработчики имеют try/except, другие — нет
- Безмолвные сбои при отправке уведомлений (`app/bot/handlers/add.py:509`)
- Нет структурированных ответов об ошибках

---

### 3. Магические числа

**Файл:** `app/bot/handlers/add.py:494`

```python
NOTIFY_THRESHOLD = Decimal("5000")
```

Должно быть в конфигурации.
